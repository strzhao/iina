**三条跨维度根因**（多数 P0/P1 的共同源头）：

1. **`MediaLibraryStore` 单例 + `MediaItem` 跨线程共享可变引用** —— probeQueue（后台写）↔ 主线程（读）↔ `saveIndex`（NSKeyedArchiver 编码）全无同步。是 P0 数据竞争 + P1 大量同步 I/O 的共同根因。
2. **"修一个 bug 引入一个副作用"模式** —— 实时读 watch-later（修进度→引入同步 I/O）、`probedKeys` 防循环（→ 防了正当重试）、池化修串行（→ `cancelAllOperations` 丢在途任务）、rescan 保留缓存（→ probedKeys 不随 rescan 重置）。缺整体的状态 / 缓存 / 取消设计。
3. **UI 层缺增量更新 + 缺状态机** —— 全量 `reloadData()`、无扫描状态机、probe / 缩略图无取消。

## 🔴 P0 — 正确性 / 数据完整性 / 可用性硬伤

### P0-1 [架构] MediaItem 跨线程数据竞争
- **证据**：写 `MediaLibraryStore.swift:339-352`（probeQueue 后台直接写 `item.width/height/duration/year/bitrate/videoCodec`）；读 `MediaItemCollectionViewItem.swift:358,376,432`（主线程）；`saveIndex`（`:291`，在 `:362` main.async 块内 NSKeyedArchiver 编码遍历 items）与后台写并发；`MediaItem.swift:53-65` 字段全是普通 `var`、NSObject 子类无锁 / actor。
- **根因**：同一 MediaItem 引用被后台写 + 主线程读 / 编码，无同步。
- **当前状态**：仍存在（`thumbnailPath` 写入在主线程回调 `MediaThumbnailer.swift:236`，非本条竞态源，已排除）。
- **影响**：TSan 可检出 data race；轻则撕裂值（duration 半写→进度异常），重则崩溃。`metadataProbed` 通知触发 configure 重读同一 item，竞争窗口是常态。
- **修复方向**：probe 字段赋值全部切 `DispatchQueue.main.async`；或 MediaItem 改值类型 / actor 隔离。

### P0-2 [性能] 缩略图 backoff 退避 4 次后丢任务 → 永久占位图
- **证据**：`MediaThumbnailer.swift:162-169` 池满时仅重试 4 次（~1.6s），之后 `completion(nil)` 不入等待队列；池大小 3（`:38`）；configure 清空（`MediaItemCollectionViewItem.swift:353`）+ 炭灰底（`:95`）无占位反馈。
- **根因**：定时退避而非 FIFO 等待队列；slot 被慢 NAS 文件占住时后续请求被丢弃。
- **影响**：大库首屏若 3 slot 被慢文件占住（各 10s timeout），第 4 张起永久占位图，slot 空闲后也不补生成。
- **修复方向**：FIFO 等待队列，slot 释放事件驱动 dequeue；生成中显示占位 spinner。

### P0-3 [架构/性能] probe 无超时 / 取消 + 串行，慢文件卡死整条队列
- **证据**：`FFmpegController.m:356` `avformat_open_input` 无超时 / 取消点；`MediaLibraryStore.swift:59` probeQueue 是 serial。缩略图有 10s timeout，probe 无对等机制。
- **影响**：NAS 抖动某文件 open_input 挂住（SMB 重协商），所有卡片元数据长期空白且无反馈。
- **修复方向**：`asyncAfter` 软超时跳过 + probedKeys 标记失败；或带 timeout 的 Operation。

## 🟠 P1 — 性能与体验的高频痛点

### P1-1 [性能] 缩略图无内存级缓存，每次滚动回读盘 + 全量解码
- **证据**：`MediaItemCollectionViewItem.swift:390-398` configure 每次都 `NSImage(contentsOf:)`；`MediaThumbnailer.swift:135` cache-hit 也读盘。全工程无 `NSCache`。
- **修复方向**：`NSCache<NSURL, NSImage>`，miss 再读盘。

### P1-2 [架构/性能] continueWatchingItems() O(history×items) 全扫 + 每 entry 同步读盘
- **证据**：`MediaLibraryStore.swift:184-211` 每 entry 可能回退 `items.first{}` 全扫，每 entry 同步 `playbackProgressFromWatchLater` 开 StreamReader 读首行。调用链：`HistoryController.save()` → `.iinaHistoryUpdated` → `refresh()`。
- **当前状态**：逻辑已修复（commit 8ad46797），性能副作用是新引入。
- **修复方向**：删 md5Index 回退路径；watch-later 进度短 TTL 缓存；continueWatching 结果缓存。

### P1-3 [性能] refresh() 全量 reloadData 未 diff，进度变化整墙重建
- **证据**：`MediaLibraryViewController.swift:277` `collectionView.reloadData()`；storeScanned / historyUpdated 全量 reload。metadataProbed 仅重配 visibleItems（此项 OK）。
- **影响**：播放进度变化整墙 reload，中断滚动惯性。
- **修复方向**：historyUpdated 只刷 strip + 进度条；metadataProbed 节流；长期 diffable snapshot。

### P1-4 [性能] 缩略图"并发"池实际 3 个串行实例 + cancelAllOperations 丢在途任务
- **证据**：`FFmpegController.m:75,85` 每实例 `maxConcurrentOperationCount=1` + 开头 `cancelAllOperations`；池实现 `MediaThumbnailer.swift:159` round-robin。
- **修复方向**：池大小可调；可见优先队列；扫描时后台预生成。

### P1-5 [体验] 扫描中无进度反馈
- **证据**：`MediaLibraryViewController.swift:280` 只有静态文本「扫描中…」，无 NSProgressIndicator / 项数。
- **修复方向**：Scanner 边扫边 post 增量通知（已发现 N 项），显示 spinner + 计数。

### P1-6 [体验] 单击 vs 双击语义不一致
- **证据**：主网格 `MediaLibraryViewController.swift:339` 单击即打开 / 下钻；继续观看 `ContinueWatchingView.swift:104` 单击打开；剧集列表 `EpisodeListViewController.swift:42` 双击打开。另：`ContinueWatchingView.swift:26` 注释写 "double-clicks" 但 `:104` 实际单击——注释 / 实现不一致。
- **修复方向**：统一为「单击高亮 + 预览，双击打开」。

### P1-7 [体验] showWindow 重开窗口不 refresh / rescan → 新增媒体不浮现
- **证据**：`AppDelegate.swift:1004` showMediaLibraryWindow 不调 refresh / rescan；`MediaLibraryWindowController.swift:43` override 只 center + activate。仅启动检查更新路径才 refresh，且只读缓存。
- **修复方向**：showWindow override 调 `MediaLibraryStore.shared.rescan()`（异步，缓存兜底）。

## 修复路线图（4 阶段，每阶段一个独立 autopilot run）

> 阶段间有依赖：Phase 0 数据层隔离是 Phase 1 缓存 / 增量的前提。

### Phase 0 — 数据层隔离与正确性（P0）
- P0-1：MediaItem 字段写入切主线程（probe 完成 + thumbnailPath 回调在 main.async 赋值）
